## Limits

- The interface tests use a DOM/event fixture and the soundtrack tests use audio stubs.
- The browser check used Chromium only; Safari and real-speaker playback were not tested.
- **No job was sent to IonQ.** Every IonQ test used a fake provider that mirrors qiskit-ionq's interfaces (`run`, `retrieve_job`, `cancel_job`, `client.estimate_job`, `IonQJobFailureError`, `IonQAPIError`). The first real run with a key should use the free `simulator` target.
- Real QPU jobs need device access and may incur charges.

## Quantum execution notes

**Check circuit** grades exactly on the local simulator. When the service is running, Qiskit independently regrades the same contract, and progress is awarded only if Qiskit agrees. IonQ runs sample prepared inputs on the IonQ cloud simulator or a QPU. Their results are shown beside the ideal prediction and never decide grading. The service keeps the IonQ key on the server, offers paid QPUs only with `IONQ_ENABLE_QPU=1`, and requires explicit confirmation for each paid job.

The optional Qollab-patched dependency profile is pinned in `backend/requirements-qollab.txt`; the tests used the standard pinned dependencies in `backend/requirements.txt`.
